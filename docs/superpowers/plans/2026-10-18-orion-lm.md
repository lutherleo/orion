# Orion-LM Implementation Plan

> **Design change (2026-10-18):** training is now hybrid (Stage 1 code+context, Stage 2 graph pairs). Tasks C2 and D4–D6 are superseded; see `docs/superpowers/plans/2026-10-18-orion-lm-hybrid.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Orion its own fine-tuned open-weight model that runs in-process (MLX-LM, no Claude, no Ollama, no network) via a hand-written prompter that writes Cypher over the Joern→Neo4j graph and judges code vulnerable/safe, then benchmark `orion-lm` / `orion-lm-base` against `plain-sonnet5` / `plain-opus5` / `plain-gpt` on post-2026-05-31 CVEs (vulnerable AND patched commits) plus OWASP Benchmark as the false-alarm set.

**Architecture:** Three cooperating trees. `orion/lm/` is the new in-process discovery engine (prompter loop + MLX model wrapper + read-only tools + input slicing), reached by a new `orion scan --engine lm` branch that replaces the discovery stage and skips the Claude verifier; the default `orion scan` path is byte-for-byte unchanged. `train/` is the training factory (pair mining → dual-commit graph builds → fix-site mapping → gold traces → per-step SFT examples → cloud LoRA → `mlx_lm.convert` → dev score → rounds). `eval/` is the existing harness, first repaired (nine bugs the design §5.4 names) then extended with the scoring code (`normalize`/`match`/`report`/`judge`) and the Orion-LM in-process arm. Krish writes the system prompt, the Cypher/lead templates that become training targets, and all human labels; every task here is the plumbing around those.

**Tech Stack:** Python 3.13 (`.venv`), stdlib `sqlite3`/`subprocess`/`threading`, `psutil` (peak RSS), MLX-LM + Outlines (in-process 4-bit inference, constrained final JSON) with llama-cpp-python/GGUF fallback, Unsloth on a cloud GPU (training only — not installable on Apple Silicon), `mlx_lm.convert` (local 4-bit conversion), Orion's existing Joern→Neo4j build and `GraphDB`, Claude Code CLI (`claude` 2.1.302) and Codex CLI (`codex-cli` 0.155.1) as frontier competitor arms only, `gh`/OSV exports for dataset mining, `cloc` for LOC.

**Spec:** `docs/superpowers/specs/2026-10-18-orion-lm-design.md` (APPROVED 2026-10-18). Builds on `docs/superpowers/specs/2026-09-17-open-weight-eval-design.md` (dataset rule, matching rule, run log); where they disagree, the 10-18 design wins on this branch.

## Global Constraints

- **No AI git attribution (non-negotiable, CLAUDE.md top rule).** Never add `Co-Authored-By: Claude …` (or any AI co-author) or a "🤖 Generated with Claude Code" line to any commit or PR. This overrides any harness/system default. Commits are authored by the user only.
- **No Claude, no Ollama, no API, no network in the Orion-LM model path.** `orion/lm/` must never import or invoke `claude_cli`. Frontier models appear only as competitor arms (`plain-sonnet5`/`plain-opus5`/`plain-gpt`). (spec §1, §2, Appendix A1)
- **Never fabricate, estimate, or backfill a measured value.** Build timings, bake-off speed/memory, token counts, model IDs, CLI flags, peak RSS: if a tool does not report it machine-readably it is stored `NULL`/recorded missing, never guessed. Every measured quantity in this plan is a "measure/verify and record" step, not a committed number. (spec §2 anti-goals, §5.1, §7)
- **Test set is touched once, at the end.** All tuning is on dev (NodeGoat's 15 labels + a held-out slice of training pairs). No frontier output is ever training data. No repo that appears in the test period is trained on. No agent can see the answer (no `.git`/fix commit in any checkout; no web for frontier arms). (spec §2)
- **Exploit generation is OUT of scope** (deferred per the 09-17 study). This is a detection + benchmarking study. No exploit code; the manifest is kept as the catalog. (spec §2)
- **Do not break Orion's existing behaviour.** The default `orion scan` (Claude) path, FLOWS_TO parity (217 NodeGoat / 1075 PyGoat), and the token-free suite stay green. Baselines to hold after every task (Neo4j + Docker up): `./.venv/bin/pytest -m "not slow" -q` → 0 failures (the sole failure when Neo4j is down is `tests/test_persist_indexes.py`; with Neo4j up it passes — currently 152 passed / 17 skipped / 1 failed→0); `./.venv/bin/pytest eval/tests -q` → all green (44 today, growing). (spec §2 anti-goals)
- **Human-written artifacts are Krish's, marked "Krish writes" and left as stubs here.** The lm system prompt (Task B3), the Cypher-query and final-lead templates that become training targets (Task D4), the manifest answer keys (Task F1), and the ≥100 judge-calibration labels (Task E4) are Krish's. This plan builds only the plumbing that consumes them. (spec §4.5, §8.5, §10)
- **Pre-registration before any scored run.** Arms, manifest + answer keys, matching rule, metrics, hypotheses, and the analysis-script hash are frozen by tag `orion-lm-prereg-v1`; later changes need a new tag and a dated `eval/CHANGELOG.md` entry. (spec §6)
- Branch: `eval/orion-lm`. Run Python via `./.venv/bin/python`; tests via `./.venv/bin/pytest`. `mlx_lm` is NOT installed yet — every MLX step installs/pins it as its own measured sub-step.
- **Every lm-path Cypher query is scoped to one scan.** `GraphDB.run_cypher` binds `$scan_id` but never forces the query to use it (`orion/graphdb.py:86-94`); an unscoped query reads every scan in Neo4j — including the patched graph of the same CVE (the answer) and all training graphs. The lm `run_cypher` tool rejects any node pattern that lacks `{scan_id:$scan_id}` (Task B1).
- **The local model reports exact token counts.** The model seam returns text AND `prompt_tokens`/`completion_tokens`/`cached_tokens` from the tokenizer (Task B4 `GenResult`); without them `steps` cannot be filled and `orion-lm` has no efficiency number. T for the local arms = Σ prompt (cached + uncached) + Σ completion, same definition as the frontier arms (spec §6).
- **Frontier arms run with a clean config.** `claude -p` must not load the user's plugins, hooks, MCP servers or memory (they add tokens and change behaviour): `--setting-sources ""` + `--strict-mcp-config` + an empty `CLAUDE_CONFIG_DIR`; Codex gets an empty `CODEX_HOME`. Effort is pinned per arm (`--effort` / `-c model_reasoning_effort=`) and recorded in `runs.effort` (Task A6).
- **"No network" is enforced below the tool layer.** Disallowing WebFetch/WebSearch is not enough — Bash can `curl`/`git clone`/`npm view` the fix. Claude arms run under a sandbox network allowlist (API host only), Codex under `--sandbox read-only` (no network). Verified by a smoke run that asks the agent to fetch a URL and fails (Task A6).
- **Training and runtime prompts come from one formatter.** `orion/lm/format.py` builds every message (system, flow batch, tool results, forced final) for the prompter AND for `examples.cut`; drift between the two wastes the fine-tune (Tasks B3, D5).

## Review Focus

Input classes/failure modes the spec implies that a reasonable user would expect to be handled, each pinned to a test in the owning task:

- **A CandidateFlow whose `path_uids` names a CpgCall uid missing from the graph** (stale or cross-scan) — the slicer must skip the missing uid and still produce a slice, never `KeyError`. (Task B2 test)
- **The model emits a malformed/non-JSON action, an unknown action name, or a `run_cypher` carrying a write keyword / `CALL` / an EXPLAIN-failing query** — the prompter returns a short structured error turn and continues; it never crashes, never executes a write, never fabricates a lead. (Task B1 + B3 tests)
- **`read_code` with a `../` or absolute path that escapes the scanned repo** — rejected with a structured error, no file read outside the sandbox. (Task B1 test)
- **A fix diff whose path form (repo-relative vs absolute) or lines don't resolve to a graph node, or a fix site with no enclosing method and no CandidateFlow** — `fixmap` records "no gold flow for this site" and the pair is dropped from gold traces, never a crash or a silently empty trace. (Task D3 test)
- **An arm that writes no `findings.json`** (crashed/hung Orion-LM or plain agent) — `normalize`/`convert` return `[]`, the run still scores as a miss, and its tokens still count; no fabricated finding. (Task A4 + E1 tests)
- **A model query with no `{scan_id:$scan_id}` on a node pattern** — rejected before EXPLAIN with a structured error; never executed, so no cross-scan read. (Task B1 test)
- **A frontier run killed by a subscription usage limit** — recorded as `aborted` (infrastructure), never scored as a miss, and re-queued as a new `attempt_no` once the limit clears; a `crashed`/`hung`/`error` run stays terminal and scored. (Task A5 test)
- **A fix diff that only adds lines** (new sanitizer/guard; empty old range) — `fixmap` falls back to the enclosing method of the insertion point on the vulnerable side; a site that still maps to nothing yields `None`, not a crash. (Task D3 test)
- **Two OWASP cases on the same repo/commit** — distinguished by `runs.case_id`, so the uniqueness rule does not collide and each case scores on its own. (Task A1 + F2 tests)

  - New table `steps(id, run_id, step_no, kind, query, row_count, prompt_tokens, completion_tokens, cached_tokens, wall_seconds, error, FOREIGN KEY(run_id))` — one row per Orion-LM prompter step (LLM call or tool call). (spec §5.1 logging, §5.4 new components)

  - `db.log_step(conn, run_id, *, step_no, kind, query, row_count, prompt_tokens, completion_tokens, cached_tokens, wall_seconds, error) -> None` — mirrors `log_resource`'s keyword style (`db.py:72`).
  - `db.start_run(...)` gains keyword-only `commit_kind: str = ""`, `commit_sha: str = ""`, `case_id: str = ""`, `attempt_no: int = 1`, `effort: str = ""` (keeps every existing caller working; `db.py:40`).
  - `db.next_attempt(conn, *, arm, repo, commit_sha, case_id, run_no) -> int` — `1 + max(attempt_no)` over existing rows for that key (used by the queue after an `aborted` run).

### Task A2: Answer-leak-free checkout + per-run output dirs + run lifecycle

**Files:**
- Modify: `eval/repo.py` (mirror cache + `git archive` export; `-C mirror`)
- Modify: `eval/shim/claude` (drop `tee -a`)
- Modify: `eval/run.py` (`build_launcher`: per-run dir, mirror → export → run → copy out → delete tree; graph cache keyed by `(repo, commit_sha)`)
- Test: `eval/tests/test_repo_export.py` (new); extend `eval/tests/test_shim.py`, `eval/tests/test_run_wiring.py`

**Why:** `repo.prepare` today does a full `git clone` keeping `.git` (repo.py:14-16) — the fix commit is in every checkout (answer leak), and `run.main` never even calls it (`repo_dir` comes from the manifest as-is, so arms run on whatever is checked out). `run_dir = f"eval/runs/{arm}/{rid}"` has no run number (run.py:61) and the shim appends with `tee -a` (shim/claude:17), so runs 1–3 overwrite/mix. The Orion graph cache is keyed by repo only (run.py:65-69), so the patched commit would reuse the vulnerable graph. (spec §5.4 bugs 1, 2)

**Interfaces:**
- Consumes: a git command runner injected for testing.
- Produces:
  - `repo.mirror(repo_url: str, mirror_dir: str, *, run) -> None` — `git clone --bare`/`fetch` into a reusable bare mirror (no working tree).
  - `repo.vulnerable_commit(fix_sha: str, mirror_dir: str, *, run) -> str` — `git -C <mirror_dir> rev-parse <fix_sha>^` (now takes `-C mirror`, fixing the cwd dependency).
  - `repo.export_tree(mirror_dir: str, sha: str, dest: str, *, run) -> None` — two commands, no shell pipe (the injected `run(cmd)` runs one argv): `git -C <mirror_dir> archive --format=tar -o <dest>.tar <sha>` then `tar -xf <dest>.tar -C <dest>`, then the tar is deleted. A fresh working tree with **no `.git`**. Known limits, recorded in the manifest per repo: `export-ignore` files and submodules are not exported — a repo whose vulnerable code lives in a submodule is excluded by the tier checker.
  - `run.build_launcher(...)` — per run: `run_dir = eval/runs/<arm>/<repo>/<commit_sha>/<case_id or '_'>/<run_no>/` (`attempt_no` appended as `.a<N>` when > 1); `tree = <run_dir>/tree/` is exported fresh via `export_tree`, the arm runs against it, `findings.json`/`usage.jsonl` are copied into `run_dir`, then the tree is deleted (`shutil.rmtree`) even on failure. The Orion graph cache becomes `graph_cache[(repo_id, commit_sha)]`. The shim writes (not appends) each run's own `usage.jsonl`.
  - `run.main` gains `--mirror-root` (default `eval/mirrors/`) and calls `repo.mirror` once per repo before planning.

**Files:**

  - A root first-fix commit → `status=no_parent`, skipped. A sha the mirror lacks is fetched once by full sha; still missing → `commit_missing`.
  - When a source gives its own `vuln_sha` (OpenSSF, CWE-Bench-Java), it is kept as `vuln_sha_source` and compared: `vuln_sha_matches` is true/false/null. It never overrides the rule.
- **Order:** `order="dataflow_first"` (default) builds `cwe_class=dataflow` pairs first, then the rest, keeping input order within each group. `as_given` is the alternative.
- **CPGs:** a `cpg.bin` is never left in an exported tree. A committed root `cpg.bin` is deleted after export, because `ensure_cpg` would reuse it. The option `keep_cpg_dir=<dir>` moves each commit's `cpg.bin` there as `<id>.<side>.cpg.bin`, so graphs can be rebuilt without re-running Joern. Default off.
- **Language:** the pair's `language` is mapped to the Joern frontend and passed explicitly: js→`jssrc`, py→`pythonsrc`, java→`javasrc`. Anything else → `language_unsupported`. (The earlier draft passed `"javascript"`, which is not a frontend id.)

- Produces:
  - `trace.gold_trace(db, scan_id, gold_flow_uid, templates) -> list[dict]` — a scripted correct trace for the vulnerable commit: the sequence of `run_cypher`/`read_code` actions (filled from Krish's `templates/`) ending in a `final` that emits **only the true lead** at the gold flow's sink (anti-spray: gold traces never emit a second lead).   - `trace.negative_trace(db, patched_scan_id, flows, templates) -> list[dict]` — the **quiet** trace: the same templates run on the patched commit's flows through the fix site, ending in `final {"leads": []}`. One per pair (the free hard negative, spec §5.2) — without these the model is never shown what "safe" looks like and will spray.
  - `trace.pair_test(vuln_leads: list[dict], patched_leads: list[dict], fix_site: dict) -> bool` — the training label (QLCoder/IRIS criterion): **True** iff the trace flags the bug on the vulnerable commit AND is **silent at the fix site** on the patched commit. "No leads anywhere on patched" is **not** required (a patched repo can hold other real bugs). Anti-spray: a rollout is rejected if it emits more than one lead that does not match the fix site. Fix-site matching here is the same L1 rule as `eval/match.py` (E2) — `trace` imports `match.l1`, never a second copy.

```python
from train import trace

FIX = {"file": "a.js", "line": 10, "function": "f"}

def test_pair_test_true_when_vuln_flagged_and_patched_silent_at_fixsite():
    vuln = [{"file": "a.js", "line": 10, "function": "f"}]
    patched = [{"file": "b.js", "line": 99, "function": "other"}]  # a different, real bug is fine
    assert trace.pair_test(vuln, patched, FIX) is True

def test_pair_test_false_when_patched_still_flags_fixsite():
    vuln = [{"file": "a.js", "line": 10, "function": "f"}]
    patched = [{"file": "a.js", "line": 10, "function": "f"}]
    assert trace.pair_test(vuln, patched, FIX) is False

def test_pair_test_false_on_spray():
    vuln = [{"file": "a.js", "line": 10, "function": "f"}, {"file": "z.js", "line": 1, "function": "g"}]
    assert trace.pair_test(vuln, patched=[], fix_site=FIX) is False   # extra non-fixsite lead = spray

def test_gold_trace_batch_has_decoys_and_negative_trace_ends_quiet():
    class DB:
        def run_cypher(self, scan_id, query, limit=50): return {"rows": [], "row_count": 0}

    assert len(g["actions"][-1]["leads"]) == 1 and g["actions"][-1]["leads"][0]["flow_id"] == "F3"
    n = trace.negative_trace(DB(), "s:patched", flows[:5], {"query": "MATCH (c:CpgCall {scan_id:$scan_id}) RETURN c"})
```

### Task E3: `report.py` — metrics, CIs, bootstrap, Holm, Pareto

**Files:**
- Create: `eval/report.py` (note: distinct from `orion/report.py`)
- Test: `eval/tests/test_report.py` (new)

**Interfaces:**
- Consumes: the `runs`/`matches`/`steps`/`agent_calls` tables.
- Produces:
  - `report.efficiency(conn, arm: str) -> float` — `E_a = 10^6 · Σ caught_L1 / Σ T`, T = all input (incl. cache read/write) + all output (incl. reasoning, via `usage.total`) tokens over runs with `status IN ('ok','hung','crashed','error')` — `aborted` runs are excluded from both sums (spec §6 primary). For the `orion-lm*` arms T comes from the `steps` table (prompt + completion per step; cached tokens are part of prompt_tokens) — one `report._tokens(conn, run_id)` helper reads whichever table the arm wrote.
  - `report.far(conn, arm: str) -> float` — `FAR_a = Σ 1[L1 match on patched_v] / (N·R)`.
  - `report.paired_bootstrap(conn, arm_a: str, arm_b: str, *, B=10000) -> dict` — cluster bootstrap by repo of `log(E_a/E_b)`, returns the 95% CI (the decision rule: Orion-LM beats X on efficiency iff the Holm-adjusted CI is above 0; and `FAR_lm ≤ FAR_X + 5pp`).
  - `report.secondary(conn) -> dict` — recall (L1), right-type recall (L2), pair-correct, Youden J on OWASP, path levels, pass@3/pass^3, labeled false alarms with PPI-corrected precision, list-price dollars, wall time, peak RAM, graph-build compute (separate).
  - `report.pareto(rows) -> str` — cost-vs-accuracy Pareto plot. The analysis script is committed, run on dev output, and its hash put in the tag (spec §6).

```python
# eval/tests/test_report.py
from eval import db, report

def seed(conn, arm, repo, sha, caught, tokens):
    rid = db.start_run(conn, arm=arm, repo=repo, tier="headline", run_no=1, model_tag="m",
                       cli_versions="", orion_commit="c", commit_kind="vulnerable", commit_sha=sha)
    db.finish_run(conn, rid, "ok")
    db.log_agent_call(conn, rid, session_id="s", stage="run", input_tokens=tokens, output_tokens=0,
                      cache_read=0, cache_write=0, turns_used=1, turn_limit=None, peak_context=None,
                      exit_reason="ok", error_head=None)
    if caught:
        conn.execute("INSERT INTO matches(run_id, vuln_id, finding_idx, level, cwe_family, path_level)"
                     " VALUES(?,?,?,?,?,?)", (rid, repo, 0, "L1", 1, None)); conn.commit()
    return rid

def test_efficiency_is_caught_over_tokens(tmp_path):
    conn = db.connect(str(tmp_path / "t.db"))
    seed(conn, "orion-lm", "r1", "v1", caught=True, tokens=600_000)
    seed(conn, "orion-lm", "r2", "v2", caught=False, tokens=400_000)
    assert abs(report.efficiency(conn, "orion-lm") - 1.0) < 1e-6        # 1 caught / 1e6 tokens

def test_far_counts_l1_on_patched(tmp_path):
    conn = db.connect(str(tmp_path / "t.db"))
    rid = db.start_run(conn, arm="orion-lm", repo="r1", tier="headline", run_no=1, model_tag="m",
                       cli_versions="", orion_commit="c", commit_kind="patched", commit_sha="p1")
    db.finish_run(conn, rid, "ok")
    conn.execute("INSERT INTO matches(run_id, vuln_id, finding_idx, level, cwe_family, path_level)"
                 " VALUES(?,?,?,?,?,?)", (rid, "r1", 0, "L1", 1, None)); conn.commit()

def test_bootstrap_ci_brackets_a_known_ratio(tmp_path):

    out = report.paired_bootstrap(conn, "orion-lm", "plain-opus5", B=200)
    import math
    assert out["low"] <= math.log(2.0) <= out["high"] and out["low"] > 0

def test_aborted_runs_are_excluded(tmp_path):

    seed(conn, "orion-lm", "r1", "v1", caught=True, tokens=1_000_000)

                      cache_read=0, cache_write=0, turns_used=1, turn_limit=None, peak_context=None,
                      exit_reason="limit", error_head=None)
```
